## 问题本质

你完全正确：

1. **轮询SPI** + **FIFO_THRESHOLD_01DATA**（每次1字节）+ **RTOS任务切换** = 字节间间隔 >2μs
2. LED任务优先级低 → 被电机/USB/CAN中断
3. 中断延迟 >2μs → WS2812误判帧结束
4. 结果：显示错误数据（闪白光），下一帧恢复

### 第2阶段：低成本缓解（10分钟）

**目标**：立即降低闪白光频率

```c
// 在 BSP_LED_Init() 中，改SPI配置
hspi6.Init.FifoThreshold = SPI_FIFO_THRESHOLD_04DATA;  // 改这里
// 原来是 SPI_FIFO_THRESHOLD_01DATA
```

**效果**：
- 每次写入4字节而不是1字节
- 减少HAL轮询次数
- 闪白光频率可能降低50-70%

**优点**：只改一行代码  
**缺点**：不能彻底消除，仅治标

### 第3阶段：长期方案 - SPI DMA（1-2小时）

**目标**：彻底消除闪白光

#### 3.1 为什么DMA有效
```
轮询：CPU逐字节写入，中间可能被中断
  字节1 → [可能中断] → 字节2 → [可能中断] → 字节3 → ...
  
DMA：硬件直接搬运，CPU无权介入
  字节1-9连续发送，中断无法打断 ✓
```

#### 3.2 实现步骤

**步骤1**：CubeMX配置（见 `DMA_SOLUTION.md`）
- Connectivity → SPI6 → DMA Settings → Add SPI6 TX
- System Core → NVIC → Enable DMA interrupt
- Generate Code

**步骤2**：使用提供的代码
```bash
# 用DMA版本替换
cp bsp_led_dma.c bsp_led.c
```

**步骤3**：处理D-Cache（STM32H7特有）
- 缓冲区放在DTCM或RAM_D3
- 发送前调用 `SCB_CleanDCache_by_Addr()`

**步骤4**：互斥保护
```c
// 自动集成，无需修改
osMutexAcquire(led_mutex, osWaitForever);
// ... 发送 ...
osMutexRelease(led_mutex);
```

#### 3.3 完整迁移指南
见 `DMA_MIGRATION_GUIDE.md`

## 快速问题排查

### 如果DMA方案遇到问题

1. **编译错误 `hdma_spi6_tx` 未定义**
   → CubeMX没有生成DMA配置，重新配置

2. **编译警告 `.dtcm_ram` section未找到**
   → 改用 `.ram_d3` section（见bsp_led_dma.c注释）

3. **仍有闪白光**
   → 检查Cache处理（`SCB_CleanDCache_by_Addr`）
   → 用示波器验证PA7波形

4. **LED任务被卡死**
   → 检查互斥锁是否正确初始化
   → 检查DMA中断是否正确配置

## 性能数据

### 传输时间
```
逻辑0：高0.4μs，低0.8μs，总1.2μs
逻辑1：高0.8μs，低0.4μs，总1.2μs
1字节 = 8bit × 1.2μs = 9.6μs
9字节 = 9 × 1.2μs × 3 ÷ bit_per_byte = ~28.8μs（实际SPI编码）
```

轮询版本：
- SPI发送占用：29μs/帧 × 50Hz = 0.145% CPU时间

DMA版本：
